# Roadmap

## Этап 1. Интерактивный MVP-каркас

Статус: выполнено.

Цель: получить рабочий пользовательский сценарий из ТЗ без сложной инфраструктуры.

Готовые сценарии:

- учитель входит в систему;
- учитель видит учеников;
- учитель создаёт домашнее задание;
- ученик видит задание;
- ученик отправляет решение;
- учитель проверяет работу;
- ученик видит результат и прогресс;
- учитель создаёт занятие;
- ученик видит занятие;
- уведомления появляются внутри платформы.

## Этап 2. Backend и постоянное хранение

Статус: текущий этап.

Цель: заменить `localStorage` на API и базу данных.

Реализовано:

- Python backend без внешних зависимостей;
- PostgreSQL;
- `psycopg`;
- Docker Compose для локальной базы;
- schema init при запуске;
- seed-данные;
- PBKDF2-хеширование паролей;
- bearer-сессии;
- доступы по ролям;
- API для учеников, заданий, занятий и уведомлений;
- frontend работает через API.

Дальше в этом слое:

- вынести схему в отдельные миграции;
- добавить тесты API;
- решить, оставляем лёгкий backend или переводим на Django Rest Framework.

## Этап 3. Файлы и математический контент

Цель: довести домашние задания до реального учебного процесса.

План:

- загрузка PDF, DOC/DOCX, JPG, PNG, TXT, ZIP;
- лимит 20 МБ на файл;
- максимум 10 файлов за отправку;
- private file access;
- предпросмотр материалов;
- поддержка LaTeX через KaTeX или MathJax.

## Этап 4. Уведомления и PWA

Цель: сделать платформу удобной на телефоне.

План:

- service worker;
- installable PWA;
- device tokens;
- уведомление за 24 часа до занятия;
- отмена старых уведомлений при переносе занятия;
- внутренний центр уведомлений как fallback.

## Этап 5. Полировка и приёмка

Цель: закрыть критерии приёмки из ТЗ.

План:

- адаптивные проверки desktop/mobile;
- тесты бизнес-логики;
- Docker Compose;
- README с API, ролями и аккаунтами;
- финальная проверка доступов.
